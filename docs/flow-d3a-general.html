Intent Dynamic Code Workflow

从用户输入开始，先做发散、收敛和人工对齐，再按 Domain 分成 D3A 或 General Coding，approve 后进入自动闭环。

Core 编排 人看的中文卡片 D3A Domain General Domain 知识检索

1. 输入到人工对齐

用户输入 一句话 / 普通结构化需求 / TR3 文档
Input Adapter 抽取需求、API 语义、验收、domain hints，并判断 input maturity
raw_idea 进入 intent-discovery，以 Superpowers Brainstorming 为 baseline
structured_requirement / tr3_design_doc 跳过 Brainstorming，直接准备进入 Grill Me 收敛
Brainstorming View 只给 raw idea：把模糊想法展开成 draft spec
TR3 Adapter TR3 抽取需求 / API / DT / 验收 / 影响范围
intent-grilling Grill Me 收敛：decision tree、frontier round、critical questions
Clarification View 信息不够时给用户看关键追问；答完回到 Requirement Assessor
Requirement Assessor 判断是否足够进入 Domain / Lane / Contract 对齐
Domain Module Router 选择 d3a、general 或未来 team-domain

2A. D3A Path

D3A Domain Module domains/d3a/module.yaml
固定 Architecture Space TRAN_CFG / DO / VISP_ADP / TFC_TFI / TFE / ADP / DRV
V0 DT Domain TPRINT / FW / DPF；真实 mapping 进保密区后填写
Required Contracts D3A spec、API contract、task contract、verification contract
D3A Plan Layer 选择、DT Domain 选择、Dependency DAG、Verification Mapping
Layer Context Packet 一个 packet 只含一个 D3A Layer，避免多 Layer 上下文污染

2B. General Path

General Domain Module domains/general/module.yaml
General Registry 只保留 placeholder，不编造团队 taxonomy
Components GENERAL_COMPONENT_PLACEHOLDER 等，进入真实团队后替换
Test Domains GENERAL_TEST_PLACEHOLDER 等，进入真实团队后替换
Required Contracts task contract、verification contract；API contract 只在 API/外部行为变化时需要
General Plan placeholder component、placeholder test domain、execution units、evidence gate

3. Lane 和人工确认

Lane Resolver 根据风险、复杂度、跨模块、测试域、API 变化等选择执行强度
fast小闭环，不代表无验证
lite标准闭环
complex分阶段闭环
Contract Gate 根据 Domain + Lane 决定 task / API / verification contract
intent-alignment 把 machine contract 渲染成 Alignment View
Alignment View 用户确认任务理解、Domain、Lane、范围、完成标准
approve? 未 approve 不写代码；approve 后进入自动闭环

4. approve 后自动闭环

Automated Closure Loop Planner -> Constraints -> Knowledge Gate -> Execution -> Verification
Execution Unit 每个阶段代码变更 <= 500 LOC，每个 unit 有独立 evidence
TDD State Machine 需要测试时必须 RED -> GREEN；无 RED 不能直接 GREEN
Verification Gate 测试、build、static check、tran_build 等工具证据
Completion View 全部 gate 满足后展示 DONE 摘要
Escalation View 证据缺失、scope/contract 变化、execution unit 过大时回流给人
Knowledge Gate 只加载当前 execution unit 需要的知识
Provider Selection Matrix 根据 anchor、domain、lane 和 token 预算选择 provider
bounded grep 有代码 anchor 时先用；定位 symbol / error / file
OKL LLM Wiki；命令是 okl-query；无 anchor 有 domain 时先用
targeted CodeGraph 影响面不清楚时用；caller / callee / dependency
Context Packet 只放 summary + evidence_ref，不放长文、长日志或全仓输出
Provider 顺序：
  • 有代码 anchor：bounded grep -> CodeGraph? -> OKL?
  • 无 anchor 但有 domain：OKL -> bounded grep -> CodeGraph?
  • 无 anchor 且无 domain：Discovery / Grilling -> OKL? -> grep

一句话总结

D3A 固定 Layer / DT Domain，API Contract 必须先于实现，全部 required DT GREEN 且 tran_build PASS 才 DONE。
General 不编造真实 taxonomy，只用 placeholder module；task / verification contract 满足，required tests/builds PASS 才 DONE。
