这张图只回答一个问题：用户输入进来后，main agent session 和 subagent session 的上下文分别怎样增长、裁剪、回填和销毁。

Main agent 长会话 Subagent 短会话 人工 checkpoint OKL / grep / CodeGraph

先看图例

横向是时间，纵向是 session 类型；颜色块越深，表示该 session 正在承担更多当前上下文。
Main session

一直存在。它保存用户意图、前置对齐结果、Domain/Lane/Contract、计划和 evidence 摘要。

Subagent session

只在执行阶段创建。每个 subagent 只拿一个 execution unit 或一个 D3A Layer Context Packet。

Knowledge provider

OKL / bounded grep / targeted CodeGraph 只返回 summary / refs / keywords 和 evidence_ref。

Human checkpoint

只在前置对齐出现。批准 Alignment Pack 之前，不创建实现 subagent。

关键：subagent 的完整上下文不会回灌 main。

Main / Subagent 上下文进出规则

这是整张图最重要的运行模型。

Main Agent Session 保留什么

  • 用户原始输入和最新指令。
  • Brainstorming / Grill Me / Alignment 的结论摘要。
  • Domain、Lane、Contract Gate、approved Alignment Pack。
  • Execution unit 队列、当前状态、completion summary。
  • Subagent 回传的 summary、changed paths、evidence refs。

Subagent Session 只临时持有什么

  • 当前 execution unit 或一个 D3A Layer Context Packet。
  • 当前相关文件、局部测试、局部 provider finding。
  • 当前失败摘要和少量关键日志片段。
  • 内部搜索过程、长日志、临时推理不回填 main。
  • 任务结束后 session 销毁，只返回可审计摘要。
Main -> Subagent

IDC workflow route + approved contract + Delegation Contract + execution unit + allowed paths + relevant Context Packet。

Subagent 内部

可以做局部 grep / test / build / file read，但上下文边界锁在当前 unit。

Subagent -> Main

只返回 summary / changed paths / evidence_ref / blockers，不返回完整 session。
