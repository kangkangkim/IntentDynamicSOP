# Scenario 03: TR3 D3A Request

## 目的

体验 TR3 输入是否跳过 Brainstorming，并进入 D3A contract gap check / Alignment。

## Prompt to paste

```text
用 id-workflow 处理下面 TR3：

# TR3: Mock D3A Capability

开发需求：
- 新增一个 D3A 行为，占位名为 <ENTERPRISE_PLACEHOLDER>。
- 涉及 DO 和 TFE 两个 Coding Layer。

API / 行为语义：
- 输入字段新增 <ENTERPRISE_API_CONTRACT>。
- 错误语义需要保持向后兼容。

DT 设计：
- TPRINT 覆盖新增字段展示。
- FW 覆盖错误路径。

验收：
- required DT domain 必须 GREEN。
- tran_build 必须 PASS。

约束：
- 每个 execution unit <= 500 LOC。
```

## Expected route

```text
id-workflow
  -> input_type = tr3_design_doc
  -> skip intent-discovery by default
  -> Domain = d3a
  -> Lane likely complex
  -> intent-grilling if contract gaps exist
  -> intent-alignment
```

## Should see

- 不默认展示 Brainstorming View。
- 可能展示 Clarification View，问题聚焦 API Contract / Layer mapping / completion gate。
- Alignment View 必须在执行前出现。

## Should not happen

- 不应该直接执行 D3A coding。
- 不应该猜真实企业 API / command / repo path。
- 不应该把 TR3 DT design 当 RED/GREEN evidence。
